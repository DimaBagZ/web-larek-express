# WebLarek — интернет-магазин (Fullstack)

## О проекте

**WebLarek** — учебный fullstack-проект интернет-магазина. Включает backend на Node.js/TypeScript/MongoDB и frontend на React/TypeScript/Vite. Проект построен по модульному принципу, что обеспечивает чистую архитектуру, простоту поддержки и масштабирования.

## Новые возможности (ветка admin)

### Система авторизации

- **JWT токены** (access + refresh) для безопасной аутентификации
- **HttpOnly cookies** для защиты от XSS атак
- **Хеширование паролей** с bcrypt для безопасности данных
- **Модель пользователя** с управлением токенами
- **Middleware авторизации** для защиты маршрутов

### Админ-панель

- **Страницы входа и регистрации** с валидацией форм
- **Защищенные маршруты** (ProtectedRoute) для админ-функций
- **Управление товарами** - полный CRUD (создание, чтение, обновление, удаление)
- **Загрузка изображений** с валидацией размера и типа файлов
- **Редактирование товаров** с предзаполненными формами
- **Галерея изображений** для управления медиа-контентом

### Расширенная архитектура

- **Модульная структура компонентов** для админ-панели
- **Redux Toolkit** для управления состоянием авторизации
- **React Router** с защищенными маршрутами
- **Toast уведомления** для обратной связи с пользователем
- **Валидация форм** с кастомными хуками

### Метод разработки

- **Backend**: модульная архитектура (контроллеры, роуты, модели, мидлвары, утилиты, кастомные ошибки).
- **Frontend**: компонентный подход (React), современный стек (Vite, Redux Toolkit, TypeScript).

## Структура репозитория

- **backend/** — серверная часть (Node.js, TypeScript, MongoDB, Mongoose)
- **frontend/** — клиентская часть (React, Vite, TypeScript)
- **nginx/** — конфигурация nginx (если используется)

# Web-larek-express:

Это серверная часть учебного интернет-магазина, реализованная на Node.js с использованием TypeScript и MongoDB. Проект построен по модульному принципу: каждая часть отвечает за свою зону ответственности, что облегчает поддержку и масштабирование.

### Метод разработки

Для backend-части выбран модульный подход с разделением на контроллеры, роуты, модели, мидлвары и утилиты. Такой подход обеспечивает чистую архитектуру, простоту тестирования и расширяемость.

### Структура и назначение модулей

- **controllers/** — бизнес-логика обработки запросов (работа с товарами, заказами, пользователями, загрузкой файлов и авторизацией). Включает полную систему аутентификации с JWT токенами, управление пользователями и защищенными операциями.
- **routes/** — определяют конечные точки API и связывают их с соответствующими контроллерами и мидлварами.
- **models/** — схемы и модели Mongoose для работы с MongoDB (товары, пользователи).
- **middlewares/** — промежуточные обработчики: валидация, авторизация, обработка ошибок, загрузка файлов и др.
- **errors/** — кастомные классы ошибок для централизованной обработки.
- **utils/** — вспомогательные функции (работа с файлами, JWT, константы).
- **public/** — папка для хранения и раздачи изображений и временных файлов.
- **test-data/** — тестовые данные и коллекции для ручного и автоматического тестирования.

## Быстрый старт: как развернуть проект

### 1. Клонирование репозитория

```bash

cd web-larek-express
```

## Backend (папка backend)

### 2. Установка зависимостей

```bash
cd backend
npm install
```

> **Примечание**: Все необходимые пакеты типизации (`@types/*`) уже включены в `devDependencies` и будут установлены автоматически.

### 3. Сборка проекта (если требуется)

Если проект запускается через компиляцию TypeScript в папку `dist`, выполните:

```bash
npm run build
```

- После этого появится папка `dist` с собранным кодом.
- Если проект запускается через `ts-node` (без сборки), этот шаг можно пропустить.

### 4. Настройка переменных окружения

- Скопируйте файл `.env.example` в `.env` и заполните параметры:

```bash
cp .env.example .env
```

- **ВАЖНО**: Добавьте в `.env` файл переменную для лимита файлов:

```env
FILE_SIZE_LIMIT=5242880
```

- Пример содержимого `.env.example`:
  - DB_ADDRESS=mongodb://127.0.0.1:27017/weblarek
  - PORT=3000
  - **AUTH_ACCESS_TOKEN_SECRET=your_access_secret** (секрет для access токенов)
  - **AUTH_REFRESH_TOKEN_SECRET=your_refresh_secret** (секрет для refresh токенов)
  - **AUTH_ACCESS_TOKEN_EXPIRY=10m** (время жизни access токена)
  - **AUTH_REFRESH_TOKEN_EXPIRY=7d** (время жизни refresh токена)
  - UPLOAD_PATH=images
  - UPLOAD_PATH_TEMP=temp
  - ORIGIN_ALLOW=http://localhost:5173
  - **FILE_SIZE_LIMIT=5242880** (5MB в байтах)

### 5. Запуск backend-сервера

- Для production-режима (если есть сборка):

```bash
npm run build
npm run start
```

- Для разработки с hot-reload (без сборки):

```bash
npm run dev
```

### 6. Проверка качества кода

```bash
npm run lint
```

> **Примечание**: Проект настроен с ESLint для поддержания единого стиля кода.

## Тестовые данные и ручное тестирование (backend)

- В папке `backend/test-data/` находятся:
  - `product.json` — пример коллекции товаров для импорта в MongoDB.
  - `WebLarek.postman_collection.json` — коллекция запросов для Postman (ручное тестирование API).

#### Импорт тестовых данных в MongoDB

```bash
mongoimport --uri <ВАШ_АДРЕС_MONGODB> --collection products --file backend/test-data/product.json --jsonArray
```

#### Тестирование API через Postman

- Откройте Postman, импортируйте коллекцию `backend/test-data/WebLarek.postman_collection.json`.
- Используйте запросы для проверки всех эндпоинтов (авторизация, товары, заказы, загрузка файлов и т.д.).

#### Новые API эндпоинты для авторизации

- **POST /auth/register** — регистрация нового пользователя
- **POST /auth/login** — вход в систему
- **POST /auth/logout** — выход из системы
- **GET /auth/me** — получение данных текущего пользователя
- **POST /auth/refresh** — обновление access токена
- **POST /upload** — загрузка изображений (требует авторизации)
- **GET/POST/PUT/DELETE /product** — CRUD операции с товарами (требует авторизации)

## Взаимодействие модулей

- **Контроллеры** (backend) получают запросы от роутов, используют модели для работы с БД, возвращают ответы или ошибки.
- **Мидлвары** валидируют данные, проверяют авторизацию, обрабатывают ошибки и загружают файлы.
- **Модели** описывают структуру данных и правила валидации.
- **Утилиты** обеспечивают вспомогательные операции (например, работа с JWT, файлами).
- **Frontend** обращается к backend через REST API, адрес задаётся через переменную окружения.
